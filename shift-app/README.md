# シフト管理アプリ

## 概要

従業員がシフト希望を提出し、管理者がその希望を確認・確定できるシフト管理アプリです。
一般ユーザーと管理者で権限を分け、それぞれ利用できる機能を分けています。

## 作成した目的

ポートフォリオとしてWebアプリケーションを開発するにあたり、「学習用のアプリではなく、実際に利用できるものを作りたい」と考えました。

そこで、現在勤務しているアルバイト先ではシフト管理が紙で行われていることに着目し、業務の効率化につながるシフト管理アプリを開発しました。

また、以前勤務していた職場ではオンラインでシフトを確認できるシステムが導入されており、その利便性を実感していました。その経験を参考に、実際の利用シーンを意識しながら設計・実装を行っています。

開発を通して、Flaskを用いたWebアプリケーション開発、SQLiteによるデータベース操作、ユーザー認証や権限管理などの技術を学ぶことも目的としています。現在も機能改善を継続し、実際の運用を想定したアプリケーションとして品質向上に取り組んでいます。

## 工夫した点

### ユーザーの役割に応じた権限管理

**課題**

一般ユーザーと管理者が同じ機能を利用できると、一般ユーザーが他の従業員のシフトを閲覧・編集できてしまい、誤操作や情報管理上の問題が発生する可能性がありました。

**対応**

ログインユーザーの権限に応じて利用できる機能を分け、一般ユーザーは自分のシフト管理のみ、管理者は全従業員のシフト確認や確定処理を行えるようにしました。

**効果**

利用者ごとに必要な機能だけを表示することで操作性を向上させるとともに、権限に応じた安全なシフト管理を実現しました。

### シフトの重複登録を防ぐ仕組み

**課題**

管理者が誤って同じシフトを複数回確定すると、重複したデータが登録され、シフト情報の整合性が保てなくなる可能性がありました。

**対応**

シフトを確定する前に、同じ内容のシフトが既に登録されているかをデータベースで確認し、重複する場合は登録を行わないようにしました。

**効果**

重複データの登録を防止し、シフト情報の整合性を維持できるようにしました。また、管理者の誤操作による登録ミスを防ぐ仕組みとしています。

### 管理者の作業負担を軽減する画面設計

**課題**

管理者がシフトを確定した後も、確定済みのシフトが一覧に表示されたままだと、未確定のシフトとの区別がつきにくくなり、確認作業の負担が増えると考えました。

**対応**

シフトを確定した時点で、管理者画面の一覧から自動的に非表示になるようにしました。これにより、管理者は未確定のシフトのみを確認できるようにしています。

**効果**

確認が必要なシフトだけが表示されるため、一覧が見やすくなり、シフト確定作業を効率的に行えるようになりました。

### 実際の業務を想定した機能設計

**課題**

学習目的だけのアプリでは、実際の業務で発生する課題や利用者の使いやすさを十分に考慮できないと考えました。

**対応**

現在勤務しているアルバイト先でのシフト管理方法を参考にし、店長と従業員それぞれの操作を想定しながら機能を設計しました。また、機能を追加する際は、「実際に利用する人にとって操作しやすいか」という視点を重視して改善を行いました。

**効果**

実際の運用を意識した設計とすることで、学習用ではなく、現場での利用を想定した実用性の高いアプリケーションを目指しました。

## 苦労した点

### ユーザー認証と権限管理

**問題**

ログイン状態の管理や、一般ユーザーと管理者で利用できる機能を分ける仕組みの実装に苦労しました。

**対応**

セッション管理の仕組みやログインユーザーの情報の扱い方を調べながら実装を進め、ログインしているユーザーの権限に応じてアクセスできる機能を制御するようにしました。

**学び**

認証機能はログインできれば終わりではなく、利用者ごとに適切な権限を設定することが、アプリケーションの安全性や利便性につながることを学びました。

### データベース設計の変更

**問題**

開発途中で勤務終了時間を追加することになり、既存のデータベース設計では必要な情報を十分に管理できないことに気付きました。

**対応**

シフト情報を管理するテーブルに勤務終了時間を追加し、それに合わせて登録処理、編集処理、一覧表示の処理を修正しました。

**学び**

データベースの設計を変更する場合、テーブル構造だけでなく、入力フォーム、登録処理、編集処理、表示画面など複数の箇所に影響が出ることを学びました。機能追加を行う際は、事前にデータの持ち方や影響範囲を確認することが重要だと感じました。

### シフト確定機能の実装

**問題**

シフト希望として登録されたデータを、管理者が確認したうえで確定シフトとして保存する処理の流れを考えることに苦労しました。また、確定処理を行う際に、同じシフトが複数回登録されてしまう問題も発生しました。

**対応**

シフト希望データと確定シフトデータの役割を分け、管理者が確定操作を行ったタイミングで確定シフトとして保存するようにしました。また、保存前に既存データを確認し、重複するシフトは登録しないようにしました。

**学び**

データを登録するだけでなく、「どのタイミングで、どのデータを、どの状態として扱うか」を考えることが重要だと学びました。機能を実装する際は、画面上の操作だけでなく、データの流れや状態の変化を整理する必要があると感じました。

### エラーの調査と解決

**問題**

開発中にはデータベース関連やテンプレート関連など、さまざまなエラーが発生し、原因を特定することに苦労しました。

**対応**

エラーメッセージやログを確認しながら原因を切り分け、必要に応じてAIやWeb上の情報も活用しながら解決方法を調査しました。提案された内容をそのまま適用するのではなく、実際に動作を確認しながら理解を深め、問題を解決しました。

**学び**

エラーが発生した際は、解決策を探すだけでなく、原因を理解したうえで修正することが重要だと学びました。また、AIを活用する場合も、内容を理解しながら検証することの大切さを実感しました。

## 今後の改善点

### UI・UXの改善

現在は機能の実装を優先しているため、デザインはシンプルな構成となっています。今後はレイアウトや配色、操作性を改善し、初めて利用する人でも直感的に操作できる画面を目指したいと考えています。

### テストコードの追加

現在は動作確認を手動で行っています。今後はテストコードを作成し、機能追加や修正を行った際にも品質を維持できるよう改善したいと考えています。

### コード構成の改善

機能の追加に伴いコード量が増えてきたため、ファイル構成や処理の責務を見直し、保守性や可読性を向上させたいと考えています。

### FastAPIへのリファクタリング

現在はFlaskを使用して開発していますが、今後はFastAPIを用いてAPI化を行い、より実務に近いアプリケーション構成についても学習していきたいと考えています。

## 起動方法

1. リポジトリをクローン

	```bash
	git clone <リポジトリURL>
	```

2. プロジェクトフォルダへ移動

	```bash
	cd shift-app
	```

3. 必要なライブラリをインストール

	```bash
	pip install flask werkzeug
	```

4. アプリケーションを起動

	```bash
	python app.py
	```

5. ブラウザでアクセス

	以下のURLへアクセスしてください。

	http://127.0.0.1:5001
